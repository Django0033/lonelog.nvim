1. INTRODUCTION                                        *lonelog-intro*

lonelog.nvim is a solo tabletop RPG toolkit for Neovim. It provides oracles,
dice rolling, notation insertion, tag and scene navigation, inline tables,
and clock/track/timer tracking — all in pure Lua with zero external
dependencies.

The plugin implements the Lonelog notation standard (v1.4.1) by Roberto
Bisceglie, a structured markdown format for solo RPG session logs.

Key features:
  - Dice engine: 2d6+3, 2d20kh1, 4d6!, 6d6>>4, 2d6>7
  - Oracle system: Fate, Binary, Mythic with persistent chaos factor
  - Tag navigation: NPCs, locations, threads, PCs, foes, rooms, inventory
  - Scene navigation: main, flashback, sub-scenes, thread scenes
  - Progress elements: clocks, tracks, timers with smart increment
  - Inline tables: range tables and bracket shorthand
  - Tag autocomplete with relevance sorting
  - Inline rolling: dice, table lookups, generator blocks
  - Session headers with auto-numbering and date
  - Campaign YAML frontmatter
  - Narrative excerpt blocks, meta notes, dialogue syntax
  - Multi-line tags for detailed descriptions
  - Combat blocks: [COMBAT] / [/COMBAT] tactical encounter delimiters
  - Dungeon Status: auto-collected room tags under === Dungeon Status ===
  - Telescope integration (optional, auto-detected)
  - 29 syntax highlight groups
  - Zero dependencies (pure Lua)

3. CONFIGURATION                                       *lonelog-config*

Call setup() with an optional table of overrides. All keys and defaults:
>
  require("lonelog").setup({
    -- Picker: "auto" (detect Telescope), true (always Telescope),
    --         false (native sidebar)
    use_telescope = "auto",

    -- Native sidebar width
    sidebar = { width = 50 },

    -- Floating result window
    float = {
      border = "rounded",
      height = 0.4,    -- fraction of editor height
      width  = 0.6,    -- fraction of editor width
    },

    -- Oracle settings
    oracle = {
      default_table = "fate",          -- "fate", "binary", or "mythic"
      persist_chaos = true,             -- save chaos factor to disk
      chaos_file = "chaos_factor.json", -- filename in stdpath("data")/lonelog/
    },

    -- Dice safety limits
    dice = {
      max_dice  = 100,  -- maximum dice per roll
      max_sides = 1000, -- maximum sides per die
    },

    -- Prompt for scene context when inserting scene markers
    prompt_for_scene_context = true,

    -- Add-on system: disable optional features you don't use
    -- All add-ons are enabled by default.
    addons = {
      combat  = true,  -- :LonelogCombat, :LonelogRound
      dungeon = true,  -- :LonelogDungeonStatus, :LonelogRoomGo, :LonelogRoomState
    },

    -- All keymaps (see |lonelog-keymaps| for defaults)
    keymaps = {
      -- Main features
      oracle = "<leader>lO",
      dice   = "<leader>lD",
      tags   = "<leader>lT",
      scenes = "<leader>lS",
      chaos  = "<leader>lC",

      -- Notation insertion
      insert_action   = "<leader>lia",
      insert_question = "<leader>liq",
      insert_dice     = "<leader>lid",
      insert_arrow    = "<leader>li-",
      insert_conseq   = "<leader>li=",
      action_seq      = "<leader>liA",
      oracle_seq      = "<leader>liQ",

      -- Tag snippets
      tag_npc      = "<leader>ltn",
      tag_location = "<leader>ltl",
      tag_pc       = "<leader>ltp",
      tag_thread   = "<leader>ltt",
      tag_ref      = "<leader>ltr",
      tag_foe      = "<leader>ltf",
       -- Other
       combat_block    = "<leader>lB",
        dungeon_status  = "<leader>lK",
        room_go         = "<leader>lG",
        room_state      = "<leader>lJ",
        insert_round    = "<leader>lr",
       session_summary = "<leader>lE",
       insert_result = "<leader>lI",
       scene_marker  = "<leader>lm",
      roll_line     = "<leader>lr",
      complete_tag  = "<C-l>c",

      -- Quick dice (1dN)
      d4   = "<leader>ld4",  d6  = "<leader>ld6",
      d8   = "<leader>ld8",  d10 = "<leader>lda",
      d12  = "<leader>ldb",  d20 = "<leader>ldw",
      d100 = "<leader>ldc",
    },
  })
<

Config key: use_telescope~
  "auto"  - Use Telescope if the plugin is installed, native sidebar otherwise.
  true    - Always use Telescope (error if not installed).
  false   - Always use the built-in sidebar picker.

Config key: addons~
  Control which optional add-on modules are loaded. Each add-on registers its
  own commands and keymaps only when enabled. All default to true.

    addons = {
      combat  = true,   -- :LonelogCombat, :LonelogRound
      dungeon = true,   -- :LonelogDungeonStatus, :LonelogRoomGo, :LonelogRoomState
    }

  Set to false to disable individual add-ons and prevent their commands and
  keymaps from being registered.

  The add-on system uses a registration pattern. Each add-on's |init.lua|
  exports a table of commands and keymaps. The plugin loader iterates enabled
  add-ons and registers them automatically. Add-on keymaps are deferred until
  after |setup()| completes, so user keymap overrides are respected.

4. COMMANDS                                              *lonelog-commands*

4.1 Main picker                                    *:Lonelog* *lonelog-command-Lonelog*
>
  :Lonelog
<
  Opens the main action picker with options: Oracle, Dice, Tags, Scenes.
  Select an action to run its sub-picker or prompt.

4.2 Oracles                                    *:LonelogOracle* *lonelog-command-oracle*
>
  :LonelogOracle [table]
<
  Roll an oracle table. Optional table argument:
    fate   - Fate oracle (7 weighted outcomes, default)
    binary - Yes / No (50/50)
    mythic - Mythic style 2d10 + chaos factor

  Without arguments, opens a picker to select an oracle. For Mythic, you
  are prompted for the chaos factor (1-9) with +/- adjustment.

  Result is displayed in a colored floating window:
    Exceptional (Yes/No) - Red     (DiagnosticError)
    Yes / Yes, but...    - Green   (DiagnosticOk)
    No / No, but...      - Yellow  (DiagnosticWarn)
    Maybe                - Default (Normal)

  Also see |lonelog-oracle|.

4.3 Dice                                          *:LonelogDice* *:LonelogDiceRoll*
                                                    *lonelog-command-dice*
>
  :LonelogDice
  :LonelogDiceRoll 2d6+3
  :LonelogD4
  :LonelogD6
  :LonelogD8
  :LonelogD10
  :LonelogD12
  :LonelogD20
  :LonelogD100
<
  LonelogDice     - Interactive prompt for dice notation.
  LonelogDiceRoll - Roll a specific notation directly. Has command-line
                    completion for common notations.
  LonelogD4-D100  - Quick roll of 1dN.

  Also see |lonelog-notation-dice| for supported notation grammar.

4.4 Notation symbols                         *:LonelogSymbol* *:LonelogActionSequence*
                                               *:LonelogOracleSequence*
>
  :LonelogSymbol @
  :LonelogSymbol ?
  :LonelogSymbol d
  :LonelogSymbol arrow
  :LonelogSymbol conseq
  :LonelogActionSequence
  :LonelogOracleSequence
<
  Insert Lonelog notation symbols into the buffer:
    @       - Action marker
    ?       - Oracle question marker
    d       - Dice roll prefix (d:)
    arrow   - Result arrow ( -> )
    conseq  - Consequence (=>)

  LonelogActionSequence inserts a 3-line action template:
>
    @ [action]
    d: [roll] -> [outcome]
    => [consequence]
<
  LonelogOracleSequence inserts a 3-line oracle template:
>
    ? [question]
    -> [answer]
    => [consequence]
<

4.5 Tags                    *:LonelogTag* *:LonelogTags* *lonelog-command-tags*
>
  :LonelogTag npc
  :LonelogTag location
  :LonelogTag pc
  :LonelogTag thread
  :LonelogTag ref
  :LonelogTag foe
<
  Insert a tag snippet at cursor. Cursor lands after the colon for
  immediate name entry.
    npc      - [N:|]       NPC tag
    location - [L:|]       Location tag
    pc       - [PC:|]      Player character tag
    thread   - [Thread:|Open]  Thread/quest tag
    ref      - [#N:|]      Reference to existing NPC
    foe      - [F:|]       Foe/combatant tag
>
  :LonelogTags
<
  Open the tag navigator picker. Browse all Lonelog tags in the current
  buffer, filterable by type. Press Enter to jump to a tag's line.

  Also see |lonelog-notation-tags| for tag format.

4.6 Scenes                         *:LonelogScenes* *:LonelogSceneMarker*
                                                  *lonelog-command-scenes*
>
  :LonelogScenes
<
  Open the scene navigator picker. Browse all scenes in the current buffer,
  sorted in chronological order. Types: main (S1), flashback (S5a),
  sub-scene (S7.1), thread scene (T1-S5). Press Enter to jump to a scene.
>
  :LonelogSceneMarker
<
  Insert a scene marker at the cursor with auto-numbering. Scans backwards
  to find the last scene ID and generates the next one:
    S1   -> S2    S5a  -> S5b   S7.1 -> S7.2
    T1-S5 -> T1-S6   S5z -> S6a (letter wraps)
    (none) -> S1

  When |lonelog-config| prompt_for_scene_context is enabled (default), you
  are prompted for a context description via |vim.fn.input()|. If you leave
  the input empty, no context is added.
    Input: "Tavern"   ->  ### S3 *Tavern*
    Input: ""         ->  ### S3

  When prompt_for_scene_context is disabled, the behavior matches the
  original Lonelog placeholder format:  ### S1 *context*

  Also see |lonelog-notation-scenes| for scene ID format.

4.7 Progress elements                    *:LonelogInsertClock*
                                        *:LonelogInsertTrack*
                                        *:LonelogInsertTimer*
                                        *lonelog-command-progress*
>
  :LonelogInsertClock [name]
  :LonelogInsertTrack [name]
  :LonelogInsertTimer [name]
<
  Smart insert or increment of progress elements (clocks, tracks, timers).

  Interactive mode (no args):~
    Prompts for the element name, then for max value (default 5) if the tag
    does not exist or is already complete. If the tag exists and is still
    in progress, increments directly without prompting for max.

  Direct mode (with args):~
    Uses the name from args, then prompts for max only if a fresh insert is
    needed. Timers never prompt for max (they have no max value).

  Behaviour by element:
    Clock   - [E:Name 0/5]  Increments +1 towards max
    Track   - [Track:Name 0/5]  Increments +1 towards max
    Timer   - [Timer:Name 0]    Decrements -1 towards 0

  If the tag is found and incomplete, the value is updated in place. If
  the tag is missing or already complete, a fresh tag is inserted at the
  cursor with the specified max (or default 5).

  Tag format:
>
    [E:Alarm 3/6]         - Event clock, name "Alarm", 3 of 6
    [Track:Escape 5/8]    - Progress track, name "Escape", 5 of 8
    [Timer:Dawn 3]        - Countdown timer, name "Dawn", 3 remaining
<

4.8 Inline rolling                      *:LonelogRollLine* *lonelog-command-roll*
>
  :LonelogRollLine
<
  Roll dice, resolve table lookups, or process generator blocks on the
  current line. The behaviour depends on the line prefix:
    d:        - Roll dice notation, append result.
                Before:  d: 2d6+3
                After:   d: 2d6+3[4, 2] = 10

    tbl:      - Roll the table's dice and resolve the entry.
                Before:  tbl: Forest (d6)
                After:   tbl: Forest d6=4 -> A deer crosses

    label:    - Look up label as table name, resolve if found.
                Before:  Apariencia: d3
                After:   Apariencia: d3=2 -> Normal
                Before:  Personalidad: d6     (no matching table)
                After:   Personalidad: d6=4

    gen:      - |lonelog-notation-gen| Batch-process indented sub-lines.

    bare dice - Roll and display.
                Before:  2d6+3
                After:   2d6+3[5, 1] = 9

  Also works on visual-selected text, using the selection as notation.

4.9 Session headers                          *:LonelogSession* *lonelog-command-session*
>
  :LonelogSession
<
  Insert an auto-numbered session header at the cursor. Scans the buffer to
  find the last "## Session N" line, then inserts the next one with today's
  date, a Recap section, and a Goals section.

  Format:
>
    ## Session 3
    2026-05-31

    ### Recap
    -

    ### Goals
    -
<
  The cursor is placed at the first Recap bullet for immediate typing.
  If no session header exists in the buffer, Session 1 is inserted.

4.10 Scene navigation                    *:LonelogScenePrev* *:LonelogSceneNext*
                                          *lonelog-command-scene-nav*
>
  :LonelogScenePrev     " Move to the previous scene
  :LonelogSceneNext     " Move to the next scene
<
  Parses all scenes in the buffer, finds which scene the cursor is currently
  in, and jumps to the adjacent scene. The view is centered on the target
  scene line.

  Behaviour:
    - Cursor before the first scene: |:LonelogScenePrev| notifies, |:LonelogSceneNext| goes to S1
    - Cursor inside a scene: jumps to the previous/next scene in ID order
    - At the first/last scene: notifies "Already at first/last scene"

4.11 Narrative blocks                           *:LonelogNarrative*
                                                  *lonelog-command-narrative*
>
  :LonelogNarrative     " Insert a narrative excerpt block
<
  Inserts a pair of delimiters for in-fiction narrative content:
>
  \---
  [cursor here, insert mode]
  ---\
<
  The cursor is placed on the blank line between delimiters in insert
  mode, ready for typing.

  Narrative blocks follow the Lonelog v1.6.0 spec convention for
  separating in-fiction prose from mechanical notation. Use them for
  found documents, memorable dialogue, or atmospheric descriptions.

4.12 Meta notes                                  *:LonelogNote*
                                                  *lonelog-command-note*
>
  :LonelogNote          " Insert a meta note
<
  Inserts "(note: )" at the cursor position with the cursor placed
  after the colon, ready for typing the note content. Works both for
  inline annotations and as the start of a line.

  Meta notes are out-of-character asides: reflections, house-rules,
  reminders, or clarifications. Use them sparingly — the game is the
  thing, and meta notes are just occasional margin comments.

  Both English and Spanish prefixes are supported:
>
  (note: testing alternate stealth rule)
  (nota: esta escena se sintió tensa)
<

4.13 Multi-line tags                             *:LonelogMultiTag*
                                                  *lonelog-command-mltag*

  :LonelogMultiTag {type}    " Insert a multi-line tag
<
  Inserts a multi-line tag template that spans three lines:

4.14 Campaign header                            *:LonelogCampaign*
                                                  *lonelog-command-campaign*
>
  :LonelogCampaign    " Insert campaign header YAML frontmatter
<
  Inserts a YAML frontmatter block at the top of the buffer with
  campaign metadata fields (title, ruleset, genre, player, PCs,
  dates, tools, themes, tone, notes). Prompts for the campaign title;
  remaining fields default to blank or today's date.

  Refuses to insert if the buffer already begins with `---` (i.e.,
  a campaign header already exists).
>
  ---
  title: Clearview Mystery
  ruleset:
  genre:
  player:
  pcs:
  start_date: 2026-05-31
  last_update: 2026-05-31
  tools:
  themes:
  tone:
  notes:
  ---

  # Clearview Mystery
<
   The cursor is placed on the `ruleset:` line for immediate editing.
   See |lonelog-notation| §6 for field descriptions.

4.15 Session summary                   *:LonelogSessionSummary* *:LonelogExportSummary*
                                         *lonelog-command-summary*
>
   :LonelogSessionSummary
   :LonelogExportSummary
<
   Session Summary shows a statistical overview of a session's content in a
   floating window, or exports it as a standalone markdown file.

   :LonelogSessionSummary - Analyse the current buffer for session headers
     (## Session N) and display a summary with scenes, tags, notation counts,
     progress elements, and dice statistics in a floating window. When there
     are multiple sessions, a picker asks which session to summarise.
     When there is exactly one session, the summary appears immediately.

   :LonelogExportSummary - Same analysis but writes the output to a markdown
     file. Prompts for the filename (default: session-N-summary.md) via
     |vim.ui.input|, then saves to the buffer's directory.

   Summary contents:
     - Session number, date, line/word counts
     - Scenes list with context
     - Tags grouped by type (NPCs, locations, threads, etc.)
     - Notation counts: actions, questions, dice, notes, dialogues
     - Progress elements: clocks, tracks, timers
     - Dice statistics: total rolls, sum of totals, average per roll
     - Complete dice breakdown with each notation and result

   Results include all data needed for session recaps, campaign logs,
   or sharing play reports. The floating window supports standard
   copy/insert keybindings (q, y, <CR>, |<leader>lI|).

4.17 Round markers                                 *:LonelogRound*
                                                    *lonelog-command-round*

   :LonelogRound     " Insert round marker with optional roster

   Inserts an auto-incremented round marker inside the current
   |lonelog-command-combat| block. A picker asks for the marker type:

   *Simple round* — inserts R{N+1} where N is the highest existing
   round number found within the enclosing [COMBAT] block.

>
   R3
<

   *Round with roster* — inserts R{N+1} Roster: followed by all
   [PC:Name|HP N] and [F:Name|HP N] tags found in the current
   combat block, providing a compact round-by-round status summary.

>
   R3 Roster: [PC:Kael|HP 8] [F:Jefe|HP 12]
<

   The roster automatically excludes dead combatants. A combatant is
   considered dead when its field starts with "dead" (case-insensitive,
   e.g. |dead|, |Dead|) or when its HP value is ≤ 0 (e.g. |HP 0|,
   |HP -3|). Edit the tag directly to mark a combatant as dead.

   If the cursor is not inside a [COMBAT] block, a warning is shown.
>
   :LonelogCombat    " Insert combat encounter block
<
   Inserts a combat block delimited by [COMBAT] and [/COMBAT], placing
   the cursor on the blank middle line in insert mode for immediate
   combat notation entry.

>
   [COMBAT]

    [/COMBAT]
<

4.18 Dungeon Status Block                    *:LonelogDungeonStatus*
                                               *lonelog-command-dungeon-status*

   :LonelogDungeonStatus " Insert or update the dungeon status block

   Scans the entire buffer for |R:| tags and groups them under a
   |=== Dungeon Status ===| header for a quick at-a-glance snapshot of
   dungeon exploration state.

   If a |=== Dungeon Status ===| block already exists, its content is
   replaced with the current list of room tags. If not, the block is
   inserted at the beginning of the buffer.

   Room tags (|[R:ID|state|...]|) are collected from anywhere in the
   buffer. If the same room ID appears multiple times, the most recent
   version is kept. Tags are sorted by numeric ID.

   Reference tags (|[#R:ID]|) and other tag types (|[N:]|, |[F:]|, etc.)
   are ignored.

   If any room tag has an |exits| field (e.g. |exits N:R3, S:R2|), the
   block is extended with a |--- Map ---| section that renders the room
   graph as ASCII arrows. Each room appears once, with forward chains
   on one line and back-references on separate lines.

   Arrow format:
     forward: --<dir>--> R<id> (<desc>)
     back:    R<id> <--<dir>-- R<id> (<desc>)

   Example - after inserting in a buffer with interconnected rooms: >

    === Dungeon Status ===
    [R:1|cleared|entry cave|exits N:R3]
    [R:2|active|barracks]
    [R:3|cleared|armory|exits S:R1, E:R4]
    [R:4|unexplored|storage|exits W:R3]

    --- Map ---
    R1 (entry cave) --N--> R3 (armory) --E--> R4 (storage)
    R2 (barracks)
    R3 <--S-- R1 (entry cave)
    R4 <--W-- R3 (armory)
<

4.19 Room Navigation                              *:LonelogRoomGo*
                                                     *lonelog-command-room-nav*

   :LonelogRoomGo " Navigate to a connected room

   Parses the |exits| field from the |[R:ID|...]| tag on the current line
   and opens a picker showing each exit direction and its destination room.

   Example - cursor on a line containing: >

     [R:3|active|almacen|exits N:R1, S:R2]

   <
   Running |:LonelogRoomGo| shows:
   >
     N -> R1 (cleared, entry cave)
     S -> R2 (active, armory)

   <
   Selecting an entry jumps to that room's line and centers the view.

   If the destination room tag is not found in the buffer, a warning is
   shown and the cursor stays in place.

4.20 Room State Editor                             *:LonelogRoomState*
                                                      *lonelog-command-room-state*

   :LonelogRoomState " Toggle states on a room tag

   Opens a picker showing all 8 dungeon states with checkmarks for the
   currently active ones. Selecting a state toggles it on or off.

   States: |unexplored|, |active|, |cleared|, |looted|, |locked|,
   |trapped|, |safe|, |collapsed|.

   Example - cursor on a line containing: >

     [R:3|cleared,looted|almacen]

   <
   Running |:LonelogRoomState| shows:
   >
     [X] cleared
     [X] looted
     [ ] active
     [ ] unexplored
     ...

   <
   Selecting |active| updates the tag to:
   >
     [R:3|cleared,looted,active|almacen]

   <
   If the current line has no room tag, a notice is shown.

6. LONELOG NOTATION                                     *lonelog-notation*

Lonelog is a structured markdown notation for solo RPG session logs
(v1.4.1 by Roberto Bisceglie, CC BY-SA 4.0).

6.1 Core symbols                              *lonelog-notation-symbols*
>
  @           - Action by main character
  @(Name)     - Action by named actor (NPC, ally, etc.)
  ?           - Oracle question
  d:          - Dice roll / resolution
  ->          - Result (from oracle or dice)
  =>          - Narrative consequence
  (nota: ...) - Meta notes and reminders (use both languages)
  (note: ...) - English meta note alias

  Insert via keymaps:
    <leader>lia / <C-l>a   - @ (generic action)
    <leader>liN / <C-l>N   - @(Name) (actor action, cursor on name)
    <leader>liq / <C-l>q   - ?
    <leader>lid / <C-l>d   - d:
    <leader>lin / <C-l>n   - (note:) / (nota:)
    <leader>li- / <C-l>-   - ->
    <leader>li= / <C-l>=   = =>
<

6.2 Tag format                                  *lonelog-notation-tags*
>
  [TYPE:Name|tag1|tag2|...]
  [#TYPE:Name]        - Reference to existing entity
<
  Tag types:
    Type      Label         Example ~
    N         NPC           [N:Jonah|friendly|wounded]
    L         Location      [L:Library|dark|quiet]
    PC        PC            [PC:Alex|HP 8]
    E         Event/Clock   [E:Alert 2/6]
    THREAD    Thread        [Thread:Main Quest|Open]
    CLOCK     Clock         [Clock:Ritual 1/8]  (alias for E)
    TRACK     Track         [Track:Escape 3/8]
    TIMER     Timer         [Timer:Dawn 4]
    INV       Inventory     [Inv:Antorcha|3]
    R         Room          [R:1|active|reception]
    F         Foe           [F:Matón|HP 6|cercano]

  Pipe-separated metadata can include:
    Regular tags      - e.g. friendly, wounded
    Changes           - trait1 → trait2  (uses Unicode RIGHTWARDS ARROW)
    Additions         - +new_trait
    Removals          - -old_trait

  Multi-line tags (span lines, close with ] on its own line):
>
  [N:Quest Log
    | Step 1: description
    | Step 2: description
  ]
<
  Use <leader>lm{n,l,p,t,r,f} or |:LonelogMultiTag| to insert.

6.3 Progress elements                        *lonelog-notation-progress*
>
  [E:Name current/max]      - Clock, counts up (starts at 0)
  [Clock:Name current/max]  - Clock alias
  [Track:Name current/max]  - Track, counts up (starts at 0)
  [Timer:Name current]      - Timer, counts down (starts at 0)
<
  Progress elements track progress toward completion:
    - Clock/Track:  Increments +1 until current >= max
    - Timer:        Decrements -1 until current <= 0

  When a tag reaches completion, the next invocation inserts a fresh
  tag (new instance). Tags with pipe-separated metadata preserve it
  when incremented.

6.4 Scene markers                            *lonelog-notation-scenes*
>
  ### S1 *context* [L:Location]
<
  Auto-numbering computes the next scene ID from the last scene in buffer:
    S1   -> S2    S5a  -> S5b   S7.1 -> S7.2
    T1-S5 -> T1-S6   S5z -> S6a (letter wraps)
    (none) -> S1

  Scene ID formats:
    S1         - Main scene
    S5a        - Flashback (letter suffix)
    S7.1       - Sub-scene (decimal)
    T1-S5      - Thread scene (thread T1, scene S5)
    T1+T2-S5   - Merged thread scene

  Context is text enclosed in asterisks (*...*).

  When |lonelog-config| prompt_for_scene_context is enabled (default),
  pressing <leader>lm prompts for context. Leaving the prompt empty
  omits the *...* section entirely.

  Navigate between scenes with <leader>l[ (prev) and <leader>l] (next)
  or |:LonelogScenePrev| and |:LonelogSceneNext| commands.

6.5 Dice notation                              *lonelog-notation-dice*
>
  Notation       Example        Description ~
  NdN            1d20           Basic roll
  NdN+M          2d6+3          Add modifier
  NdN-M          1d20-2         Subtract modifier
  NdN!           4d6!           Exploding (reroll max, up to 100 deep)
  NdNkhK         2d20kh1        Keep highest (advantage)
  NdNklK         2d20kl1        Keep lowest (disadvantage)
  NdN>>T         6d6>>4         Success counting (dice >= target)
  NdN>T          2d6>7          Sum vs target
<
  Safety limits (configurable): max 100 dice, max 1000 sides.

6.6 Inline tables                            *lonelog-notation-tables*
>
  tbl: Name (d6)
    1-3: Nothing happens
    4-5: A deer crosses
    6: Bandit ambush!
<
  Bracket shorthand (equal probability):
>
  tbl: Weather [Sunny, Cloudy, Rain, Storm]
<
  Rolls d4, assigns each option one value. Also called filtered option
  sets — each option gets exactly one face of the die.

  Rolling a tbl: line appends:  d6=4 -> A deer crosses.

  A tbl: line without dice uses the table's defined dice:
>
  tbl: Forest          rolls d6, same as tbl: Forest (d6)
<
  Duplicate table names are ignored (first definition wins).

6.7 Generator blocks                              *lonelog-notation-gen*
>
  gen: Generate NPC
    Apariencia: d3       - Table lookup (if table "apariencia" exists)
    Personalidad: d6     - Bare dice roll
    Edad: 1d6            - Dice notation
    <blank line>         - Skipped
    tbl: Equipment (d6)  - Table roll
  Other content           - Non-indented -> stops block
<
  Place cursor on the gen: line and press <leader>lr. All indented
  sub-lines are processed in place. The gen: header is not modified.

6.8 Session headers                            *lonelog-notation-session*
>
  ## Session N
<

   Auto-numbered session headers are inserted with |:LonelogSession| or
   <leader>lH. The header includes today's date, a Recap section for
   summarizing the previous session, and a Goals section for current
   objectives. The cursor is placed at the Recap bullet for immediate typing.

6.9 Narrative excerpts                          *lonelog-notation-narrative*
>
  \---
  [narrative prose...]
  ---\
<
  Narrative excerpt blocks wrap in-fiction prose between delimiters.
  Insert with |:LonelogNarrative| or <leader>lN. The cursor is
  placed on the blank line in insert mode, ready for typing.

  Use narrative blocks for found documents, memorable dialogue,
  atmospheric descriptions, or any prose that deserves emphasis
  separate from the mechanical notation.

7. ORACLE SYSTEM                                        *lonelog-oracle*

The plugin provides three oracle tables for game master decisions.

Fate oracle (weighted)~
  Result            Weight  Probability ~
  Exceptional Yes    8       8%
  Yes               23      23%
  Yes, but...       15      15%
  Maybe             28      28%
  No, but...        15      15%
  No                 8       8%
  Exceptional No     3       3%

Binary oracle (even)~
  Result  Weight ~
  Yes     50
  No      50

Mythic oracle (2d10 + chaos)~
  Result          Condition ~
  Exceptional No  final <= 4
  No              final 5-10
  Yes             final 11-17
  Exceptional Yes final >= 18

  Chaos factor range: 1-9 (default: 5).
  Modifier applied to 2d10 roll:
    CF  1  2  3  4  5  6  7  8  9
    Mod -5 -4 -2 -1  0 +1 +2 +4 +5

  Chaos factor is persistent (saved to disk when persist_chaos = true).
  Adjust via <leader>lC or :LonelogChaos.

8. TAG AUTOCOMPLETE                                *lonelog-completion*

The plugin provides automatic tag name completion when editing tags.

Auto-trigger~
  As you type after [TYPE: in a markdown buffer, matching entity names are
  suggested automatically. The cache refreshes only when the buffer changes.

Manual trigger~
  <C-l>c  (insert mode)
  :LonelogCompleteTag

Sorting~
  1. Exact match (highest priority)
  2. Prefix match
  3. Alphabetical

10. ADD-ONS (LONELOG SPEC)                              *lonelog-addons*

The Lonelog standard defines three optional add-ons. lonelog.nvim implements
the Combat and Dungeon add-ons as loadable modules that register their commands
and keymaps only when enabled. See |lonelog-config| for the |addons| config key.

The tags and notation for all three add-ons are always parseable regardless of
which add-ons are enabled:

10.1 Combat add-on                            *lonelog-addon-combat*
>
  [COMBAT]
  R1
  @(Matón A) Ataca
  d: 1d8+2 vs AC -> Fallo
  @ Ataco al Matón A
  d: 1d8+4 vs AC 11 -> Exito
  => [F:Matón A|HP 3]
  [/COMBAT]
<
  [COMBAT] / [/COMBAT]    - Delimit combat encounter
  R1, R2, R3              - Round markers
  [F:Name|stats]          - Foe/combatant tag
  Roster:                 - Full team status per round

  Use [Track:] for boss resources, [Clock:] for waves/alert.

10.2 Dungeon add-on                          *lonelog-addon-dungeon*
>
  S5 *Pasillo norte*
  @ Abro la puerta
  ? Esta cerrada?
  -> No (d6=5) => La puerta se abre.
  [R:4|active|almacen|exits N:R1, S:R2]
<
  [R:ID|state|desc|exits]  - Room tag
    States: unexplored, active, cleared, looted, locked, trapped, safe,
            collapsed
  [R:ID|cleared, looted]   - Update room state
  exits N:R2, E:R3          - Room connections
  [Clock:Antorcha X]        - Light source tracking

10.3 Resources add-on                      *lonelog-addon-resources*
>
  [Inv:Objeto|cantidad|propiedades]
  [Wealth:Oro 45|Plata 12]
  [PC:Kael|Supply d8|Ammo d6]
<
  [Inv:]       - Inventory item with quantity
  [Wealth:]    - Currency tracking
  Supply dN    - Usage dice (d12->d10->d8->d6->d4->exhausted)
  --- RESOURCES ---   - Resource status block

11. TIPS AND WORKFLOWS                                 *lonelog-tips*

Session workflow~
  Start a session with a scene marker (<leader>lm):
    ### S1 [context]
  Use notation sequences (<leader>liA / <leader>liQ):
    @ [action]
    d: [roll] -> [outcome]
    => [consequence]
  Tag persistent elements:
    [N:Guardia|alerta|armado]
    [Thread:Salvar el pueblo|Open]
  Track clocks and timers with <leader>ltc / <leader>lti.
  End scenes, roll oracles with <leader>lO when uncertain.
  Browse tags and scenes with <leader>lT / <leader>lS.

Clocks vs Tracks~
  Use [E:] (Event/Clock) for countdowns until a narrative event triggers
  (guards arrive, ritual completes, etc.). Use [Track:] for linear progress
  toward a goal (journey distance, research progress, resources gathered).

Usage dice~
  Track abstract resources with supply dice:
  [PC:Kael|Supply d8]
  When used: roll d8. 1-2 reduces the die step (d8->d6->d4->exhausted).

>
  local ln = require("lonelog")

  -- Dice
  local result, err = ln.dice.roll("2d6+3")
  -- result.display = "2d6+3[4, 2] = 9"
  -- result.total   = 9

  -- Oracle
  local oracle = ln.oracle.roll("fate")
  -- oracle.display = "Yes, but..."

  -- Chaos factor
  ln.oracle.get_chaos()       -- -> number (1-9)
  ln.oracle.set_chaos(value)  -- -> boolean (true if set)

  -- List oracle tables
  ln.oracle.list_tables()     -- -> string[]

  -- Parser
  local tags   = ln.parsers.parse_tags()
  local scenes = ln.parsers.parse_scenes()
  local summary_tags   = ln.parsers.tags_summary(tags)
  local summary_scenes = ln.parsers.scenes_summary(scenes)

  -- Inline tables
  local tables = require("lonelog.parsers.tables").parse_tables(lines)
  local entry  = require("lonelog.parsers.tables").resolve_entry(tbl, value)

  -- Inline rolling
  require("lonelog.roll_line").roll_current_line()
  local modified = require("lonelog.roll_line").process_line(line, tables)

   -- Session summary
   local sessions = require("lonelog.commands.summary").parse_all_sessions()
   -- -> { number, date, start_line, end_line }[]

   local summary_data = require("lonelog.commands.summary")
     .build_session_summary(session, all_lines, all_tags, all_scenes)
   -- -> { session, lines_count, words_count, notation, dice, progress,
   --      tags, scenes, tag_counts, scene_counts }

   local display_lines = require("lonelog.commands.summary")
     .format_summary(summary_data)
   -- -> string[] for floating window

   local export_md = require("lonelog.commands.summary")
     .export_summary(summary_data)
   -- -> string markdown

   -- Tag completion
   local comp = require("lonelog.completion")
   comp.refresh_completions()
   comp.complete_tag()
